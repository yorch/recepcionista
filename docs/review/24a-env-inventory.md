# 24a. Environment variable inventory and admin-UI classification

Slice of the "platform admin configures everything that makes sense" assessment. Read-only review; every claim was checked in code.
Method: `grep` of `process.env.X`, `env.X` (the `env: NodeJS.ProcessEnv = process.env` parameter pattern), `env?.X` over `src/**`, `scripts/**`, `next.config.ts`, `prisma/`; plus `Dockerfile`, `compose.*.yaml`, `deploy.sh`, `.env.example`, `docs/env-vars.md`.
No `process.env[...]` dynamic reads and no destructuring of `process.env` exist (verified), so the list below is complete for app code.

## 1. Headline findings

1. **133 distinct env names are read by app/scripts code** (134 raw matches minus the `NEXT_PUBLIC_` placeholder in a comment, `src/lib/csp.ts:35`), plus 10 compose/deploy-only names and `PORT`/`HOSTNAME`. docs/env-vars.md lists all 133 (nothing read in code is absent from it); `.env.example` lacks 10 (section 5).
2. **There is no platform-settings store at all.** `prisma/schema.prisma` has no settings/config model (models listed: Business, User, Call, Booking, ... Membership; none is a key/value or singleton config table). The only DB-backed overrides are per-business columns: `sms_cap_override`/`call_minutes_cap_override` (`schema.prisma:56-57`), `voice_id` (`:77`), `elevenlabs_phone_number_id`/`twilio_phone_sid` (`:90-91`), `review_url` (`:93`), `native_transfer_enabled` (`:116`), `retention_days` (`:37`), `agent_id` (`:35`).
3. **There is no admin UI.** `find src/app -path '*admin*' -name page.tsx` returns nothing; the only admin surface is JSON routes under `src/app/api/admin/` (`billing`, `jobs`, `jobs/run`, `release-tenant`, `repair-numbers`, `resync-agents`, `retention`, `users`), authenticated by the env `ADMIN_TOKEN` (`src/lib/auth.ts:108,229`) or a DB admin user. So the entire platform configuration surface (about 120 vars) is env + redeploy.
4. **Almost nothing is cached at module load**, so a DB-backed value could be applied live with no code-caching obstacle. The exceptions are: `NEXT_PUBLIC_*` (inlined at build, `Dockerfile:50-53`), `ALLOWED_DEV_ORIGINS` (`next.config.ts:27`, dev only), `PRISMA_QUERY_EVENTS` (module const, `src/lib/db/client.ts:14`), `JOBS_TICK_SECONDS`/`JOBS` (read when the runner starts, `src/lib/jobs/index.ts:602`, once per process from `instrumentation.ts`), and the CSP site-key literal (`csp.ts:36`). Changing ANY env var today still requires recreating the container (compose `env_file: .env`, `compose.production.yaml:130-131`), and with several instances env can diverge between them; a DB value would not.
5. **An encryption primitive for stored secrets already exists**: `encryptSecret/decryptSecret` AES-256-GCM keyed by `APP_SECRET_KEY` (`src/lib/totp.ts:180-207`). A write-only secrets UI can reuse it; the master key stays env.
6. **Secrets that cannot simply be moved without extra work** (provider-side coupling):
   - `ELEVENLABS_TOOL_SECRET` is copied into each ElevenLabs tool definition (`src/lib/voice/elevenlabs.ts:259-267`, header, optionally by `ELEVENLABS_TOOL_SECRET_ID`); changing it needs the existing `POST /api/admin/resync-agents` to run afterwards, otherwise every live tool call 401s.
   - `ELEVENLABS_WEBHOOK_SECRET` is generated by ElevenLabs and **shown once by provisioning and "not saved by the app"** (`src/app/api/businesses/[id]/provision/route.ts:447`, `webhook_secret_notice`): the only way to set it today is to copy it into `.env` and redeploy. This is the clearest UX gap for an admin UI.
   - `APP_URL`/`PUBLIC_BASE_URL` is baked into Twilio number webhooks (`src/lib/providers/twilio.ts:225-231`), ElevenLabs tool URLs (`elevenlabs.ts` `toolUrl = ${appUrl()}/api/voice/tools/...`), Stripe return URLs and Google redirect/webhook URLs; changing it requires re-sync of those external registrations.
7. **Inconsistent precedence of the base-URL variables** (bug-class, undocumented): `site-config.ts:7` and `twilio.ts:39` use `PUBLIC_BASE_URL || APP_URL`; `stripe.ts:158` uses `APP_URL || NEXT_PUBLIC_APP_URL` (ignores `PUBLIC_BASE_URL`); `google/config.ts:40` uses `APP_URL || PUBLIC_BASE_URL` (reverse order); `stripe-billing.ts:72` uses `PUBLIC_BASE_URL || APP_URL`. With only one set nothing breaks; with both set they disagree. An admin "public origin" setting should be a single resolver.
8. **Dev-only escape hatches are properly gated** (`insecureDevAllowed()` requires `NODE_ENV !== 'production'`, `auth.ts:97`; `DEMO_MODE` `auth.ts:235`; `GOOGLE_OAUTH_MOCK` `google/config.ts:27`; `STRIPE_ALLOW_UNSIGNED` `payments/webhook/route.ts:38`). They must NOT be exposed in an admin UI.

Legend for the tables. **Runtime?** `lazy` = read at each use (no cache; takes effect on process restart today, would be live from DB); `boot` = read once per process start; `build` = inlined at `next build`. **Scope**: P = platform-wide; T = naturally per-tenant (a platform default with tenant override is "P+T").

Classes: `MUST_STAY_ENV`, `SECRET_IN_ADMIN`, `SETTING_IN_ADMIN`, `PER_TENANT` (`ALREADY` / `SHOULD`), `DEV_ONLY`.

## 7. Documentation gaps

Checked by set comparison of names read in code against names in `docs/env-vars.md` and `.env.example`.

1. **Missing from `docs/env-vars.md`: none** for names read by app code. (Doc lists extra compose-only names `DOMAIN`, `POSTGRES_*`, `TRAEFIK_NAME`, `APP_IMAGE`, `TOOLS_IMAGE`, `DATABASE_URL_OVERRIDE`; and `REVIEW_URL`, which is explicitly documented as removed, `docs/env-vars.md:128`. `NEXT_PUBLIC_` is a comment artifact.)
2. **Missing from `.env.example`** (10 operator-settable vars): `NEXT_PUBLIC_APP_URL`, `NEXT_PUBLIC_PLAN_PRICE_DISPLAY_ES`, `NEXT_PUBLIC_PLAN_PRICE_DISPLAY_ANNUAL_ES`, `OWNER_REPLY_ENABLED`, `OWNER_REPLY_DAILY_LIMIT`, `OWNER_REPLY_REQUIRE_ATTESTATION`, `REFUND_RECONCILE_AFTER_HOURS`, `TWILIO_MESSAGING_SERVICE_SID`, `TWILIO_MESSAGING_SERVICE_PIN_SENDER`, `PRISMA_QUERY_EVENTS` (test-only; fine to omit). (`NEXT_PHASE`, `NEXT_RUNTIME` are Next-set.)
3. **Documented but unverified defaults / divergences**
   - `NEXT_PUBLIC_PLAN_PRICE_DISPLAY_ES` / `_ANNUAL_ES` are documented (`env-vars.md:61`) as build-time, but only three `NEXT_PUBLIC_*` build args exist (`Dockerfile:50-52`, compose `args` `:123-125`). If the `_ES` pair is not passed as a build arg it is never inlined and the Spanish price text silently falls back to English. Verify; likely a real bug.

   - `ELEVENLABS_WEBHOOK_SECRET` is documented as "shown once by provisioning" (true, `provision/route.ts:447`), but nothing in the app stores it; the operator must paste it into `.env` and redeploy, and until then post-call webhooks fail closed (`elevenlabs.ts:54-58`).
   - `ELEVENLABS_AGENT_ID` appears under "no" required but is silently ignored once a second business exists (`elevenlabs.ts:122-127`).
   - Undocumented defaults that live only in code: built-in forward deny list (documented in prose, but the constant `DEFAULT_DENY_AREA_CODES` `forward-number.ts:25-31` is the source of truth), `FORWARD_RING_SECONDS` clamps 10-40 (`twiml.ts:22-26`), `TRUSTED_PROXY_HOPS` clamp 1-5 (`auth.ts:251`), `VOICEMAIL_MAX_SECONDS=90` and voicemail copy are hard-coded constants (`twiml.ts`), `SIGNATURE_TOLERANCE_SECS=30*60` (`elevenlabs.ts:36`), Stripe price cache TTL 10 min (`billing/price.ts:26`), ElevenLabs request timeouts: hard-coded tuning not exposed anywhere (candidates only if tuning demand appears).

## 8. Recommendations for the admin UI (inputs to the overall assessment)

1. Introduce a `platform_settings` table (key, JSON value, encrypted flag, updated_by, updated_at) plus an audit event per change (`AuditEvent` model exists, `schema.prisma:565`). Resolve `DB value > env value > code default`, so existing deployments keep working and env becomes the bootstrap seed. Read with a short in-memory TTL (about 5-30 s) or a version counter, because the edge `proxy.ts` and per-request code cannot hit Prisma on the edge.
2. Build the first admin pages around cards: Providers (Twilio, ElevenLabs, Stripe, LLM, Email, Google, Turnstile) with write-only secrets, a "test connection", a "last rotated" stamp and, where needed, a follow-up action ("re-sync agents", "re-register webhooks"); Billing and plan caps; Voice and forwarding limits; Signup and security policy; Jobs (already has API `admin/jobs`); Public URL and branding copy.
3. Gate dangerous toggles (`BILLING_ENFORCED=false`, `SIGNUP_ALLOW_WITHOUT_CAPTCHA`, `RETENTION_JOB`, `TENANT_RELEASE_JOB`, `OWNER_PHONE_GRANDFATHER*`, `ALLOW_UNVERIFIED_BOOKING_SMS`) behind a typed confirmation and an audit row; they currently depend on the operator reading startup banners (`instrumentation.ts:59-79`).
4. Keep in env: master key, DB, break-glass `ADMIN_TOKEN`, proxy/CSP/WebAuthn identity, PORT/NODE_ENV, and everything dev-only.
5. Capture `ELEVENLABS_WEBHOOK_SECRET` at provisioning time into the encrypted store instead of printing it once (`provision/route.ts:447`).
6. Convert the three build-time vars to runtime reads: pass the Turnstile site key and plan price copy from a server component/DB instead of `NEXT_PUBLIC_*` inlining, so no rebuild is needed (the CSP edge read, `csp.ts:36`, needs the site key per request, which an env-or-cached-DB lookup can serve).
7. Unify the base-URL resolver (finding 7) before moving it into the UI.
